# 検証記録

## 実施範囲

Windows 11（build 26300）、Windows on ARM上でMSVCによるx64／ARM64ビルドと、各27件の安全な自己テストが成功しました。自己テストは実desktop切替・実キー入力・startup変更を行いません。物理／注入／修飾キー判定、固定復帰先、アクセス拒否、切替競合、API成功後の入力desktop検証、一時IPCの正常要求・不正要求・サイズ超過・無通信クライアントの期限・endpoint重複・正常停止を確認しています。

MCPは7件のPythonテスト（SDKクライアントによる初期化・ツール一覧・読み取り専用statusの往復を含む）が成功しました。ローカルの既存SDK 1.9.4でも互換動作を確認し、配布時の依存範囲内のSDK 1.30.0は[GitHub CI](https://github.com/monoqlo78/desktop-rescue/actions/runs/39197106332)で確認しました。CIはx64自己テスト、ARM64クロスビルド、両ZIPの保存に成功しています。ARM64の実行テストはローカルWindows on ARMで行いました。

利用者の追加許可後、専用のper-user配置先へARM64 exeを新規配置し、Default上で実際の常駐を起動しました。PID・実行パス・SHA-256・CLI statusの一致を確認し、正常停止／再起動も確認しました。通常の `start` をdetach実行し、起動用CLIとPowerShellは終了、ネイティブ常駐だけを残しています。自動起動・タスクスケジューラ・サービス・MCP設定は登録していません。物理キー復旧は別途の未検証事項です。

## 2026-10-19の実機アイドル計測

対象はソース `e24f635` のARM64ビルド、Windows `10.0.26300.0` / ARM64 / 論理CPU 12。常駐開始から数分経過後に追加15秒待機し、**180.0196817秒** 測定しました。終了時刻は `2026-10-19T04:06:31.6760492Z`。主に約5秒間隔、終了直前を含め44サンプルの算術平均を記載します。測定用PowerShellとGitHub操作等のCPUは対象プロセスの値に含めていません。

| 累積CPU開始 → 終了 | 1.343750秒 → 1.390625秒 |
| CPU増分 | 0.046875秒 |
| CPU平均・単コア換算 | 0.026039% |

private bytesの開始・最終値は同じ1,368,064バイト、working setは8,982,528 → 8,990,720バイト（+8 KiB）でした。この3分間で持続的なメモリ増大は確認していませんが、長期リーク不存在の証明ではありません。CPUは完全ゼロではなく、数値は当該環境・期間のプロセス会計精度に限られます。ユーザー指定の合否しきい値は設けていません。

配置先は `%LOCALAPPDATA%\DesktopRescue\0.1.0-arm64-8b526861\desktop-rescue.exe`、実行ファイルサイズ340,992バイト、SHA-256は以下です。

```text
8b5268617a64811c046531294e575696b2534282a44b544b5ef5b9333bc0913f
```

PIDは起動ごとに変わります。現在のPIDはstatusで確認してください。起動用のCLIとPowerShellは終了済みで、追加の常駐シェルを残していません。停止／再起動のコマンドは次のとおりです。

```powershell
$exe = "$env:LOCALAPPDATA\DesktopRescue\0.1.0-arm64-8b526861\desktop-rescue.exe"
& $exe status
& $exe stop
# statusがnot_runningになった後で再起動
& $exe start
```

この計測は **通常Defaultで待機する常駐本体のみ** の負荷です。別desktopのhook設置中や任意のPython MCPアダプターの追加負荷、物理キーから復帰までの応答時間を測定したものではありません。初回の別の180秒測定ではCPU増分が計測精度内で0秒でしたが、それを完全ゼロの保証として扱わず、上記の非ゼロ増分の測定値を報告しています。
